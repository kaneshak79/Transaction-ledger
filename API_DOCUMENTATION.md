
# API Documentation — Transaction Ledger API

Base URL: `http://localhost:3000`

All request and response bodies use JSON unless otherwise specified.

## 1. Health Check

**GET** `/api/health`

Checks whether the API is running.

### Success — 200 OK

```json
{
  "success": true,
  "message": "Transaction Ledger API is running"
}
```

## 2. Create Account

**POST** `/api/accounts`

Creates an account with a system-generated ID, a zero initial balance, and a creation timestamp.

### Request Body

```json
{
  "name": "Savings Account"
}
```

### Success — 201 Created

```json
{
  "success": true,
  "data": {
    "id": "ACCOUNT_UUID",
    "name": "Savings Account",
    "balance": "0.00",
    "created_at": "2026-10-27T10:00:00.000Z"
  }
}
```

The ID and timestamp are generated by the database. The balance is initialized to zero.

### Errors

- `400 Bad Request` — missing or invalid account name, or name exceeds 100 characters.
- `500 Internal Server Error` — unexpected server error.

## 3. Get Account Details and Balance

**GET** `/api/accounts/:id`

Retrieves an account and its current balance.

### Example

`GET /api/accounts/ACCOUNT_UUID`

### Success — 200 OK

```json
{
  "success": true,
  "data": {
    "id": "ACCOUNT_UUID",
    "name": "Savings Account",
    "balance": "100.00",
    "created_at": "2026-10-27T10:00:00.000Z"
  }
}
```

### Errors

- `400 Bad Request` — invalid UUID format.
- `404 Not Found` — account does not exist.
- `500 Internal Server Error` — unexpected server error.

## 4. Create Credit or Debit Transaction

**POST** `/api/transactions`

Creates a credit or debit transaction and updates the account balance atomically.

### Request Body — Credit

```json
{
  "accountId": "ACCOUNT_UUID",
  "type": "credit",
  "amount": 100.00,
  "description": "Salary deposit",
  "referenceId": "REF-001"
}
```

For a debit, use `"type": "debit"`.

### Success — 201 Created

```json
{
  "success": true,
  "data": {
    "transaction": {
      "id": "TRANSACTION_UUID",
      "account_id": "ACCOUNT_UUID",
      "reference_id": "REF-001",
      "type": "credit",
      "amount": "100.00",
      "description": "Salary deposit",
      "created_at": "2026-10-27T10:00:00.000Z"
    },
    "balance": 100
  }
}
```

### Validation Rules

- `accountId` must be a valid account UUID.
- `type` must be `credit` or `debit`.
- `amount` must be positive and have at most two decimal places.
- `description` is required and must not exceed 255 characters.
- `referenceId` is required and must not exceed 100 characters.
- A reference ID must be unique within the same account.

### Errors

- `400 Bad Request` — invalid input or insufficient balance.
- `404 Not Found` — account does not exist.
- `409 Conflict` — duplicate reference ID for the account.
- `500 Internal Server Error` — unexpected server error.

Rejected transactions do not change the account balance.

## 5. Get Transaction History

**GET** `/api/transactions/accounts/:accountId/history`

Returns an account's transaction history, newest first.

### Query Parameters

| Parameter | Required | Description |
|---|---|---|
| `type` | No | Filter by `credit` or `debit` |
| `page` | No | Page number, starting at 1; default is 1 |
| `limit` | No | Records per page; default is 10, maximum is 100 |

### Examples

Get all transactions:

`GET /api/transactions/accounts/ACCOUNT_UUID/history`

Filter credits:

`GET /api/transactions/accounts/ACCOUNT_UUID/history?type=credit`

Get page 2 with 5 records:

`GET /api/transactions/accounts/ACCOUNT_UUID/history?page=2&limit=5`

### Success — 200 OK

```json
{
  "success": true,
  "data": {
    "transactions": [],
    "pagination": {
      "currentPage": 1,
      "pageSize": 10,
      "totalRecords": 0,
      "totalPages": 0
    }
  }
}
```

The `transactions` array contains the matching records. The pagination metadata reports the requested page, page size, total matching records, and total pages.

### Errors

- `400 Bad Request` — invalid account UUID, transaction type, or pagination values.
- `404 Not Found` — account does not exist.
- `500 Internal Server Error` — unexpected server error.

## 6. Transfer Funds

**POST** `/api/transactions/transfer`

Transfers money between two different accounts. The debit and credit entries are committed together in a single database transaction.

### Request Body

```json
{
  "fromAccountId": "SOURCE_ACCOUNT_UUID",
  "toAccountId": "DESTINATION_ACCOUNT_UUID",
  "amount": 50.00,
  "referenceId": "TRANSFER-001"
}
```

### Success — 200 OK

The response includes the source and destination account IDs, transfer amount, debit transaction, and credit transaction.

```json
{
  "success": true,
  "data": {
    "fromAccountId": "SOURCE_ACCOUNT_UUID",
    "toAccountId": "DESTINATION_ACCOUNT_UUID",
    "amount": 50,
    "debitTransaction": {},
    "creditTransaction": {}
  }
}
```

The debit entry uses a reference ID ending in `-DEBIT`; the credit entry uses one ending in `-CREDIT`. Descriptions are generated automatically.

### Errors

- `400 Bad Request` — invalid input, same source and destination account, or insufficient balance.
- `404 Not Found` — source or destination account does not exist.
- `409 Conflict` — duplicate transfer reference.
- `500 Internal Server Error` — unexpected server error.

## Data Integrity

- Account balances cannot become negative.
- Transaction amounts must be positive.
- Database transactions ensure balance updates and ledger entries succeed or fail together.
- Account row locks protect concurrent balance updates.
- Duplicate transaction references are rejected within an account.
- A PostgreSQL trigger prevents transaction records from being updated or deleted.
- Transaction history is ordered by creation time descending, with transaction ID as a tie-breaker.
